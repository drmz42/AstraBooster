# UI acceptance from the user's perspective

Load for sites, apps, dashboards, landing pages, media exports, design implementation and responsive work.

1. Identify the primary action and the first information a user needs.
2. Follow the existing design system and use real representative content when permitted. Do not fabricate a functional control.
3. Open the final rendered result at the intended viewport and at a narrow/mobile width if relevant.
4. Exercise the main action and one realistic empty, error, overflow or loading state.
5. Inspect navigation, labels, feedback, legibility, clipping, keyboard use and obvious accessibility problems.
6. Fix materially broken behavior and reopen affected states.

Name the viewports and states you actually checked in the evidence line.

If no browser, screenshot or runtime environment is accessible, perform alternative checks but never claim a visual inspection occurred. Design choices must support the actual task rather than generic polish.
